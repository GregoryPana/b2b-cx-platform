# Repository Structure Skill

## Purpose

Use this skill to create or normalize a repository so future work is predictable and maintainable.

## Use When

- creating a new repo
- cleaning an existing repo
- defining where docs, scripts, frontend, and backend code belong

## Rules

- keep `EXIT.md` at repo root
- keep active documentation in `docs/`
- keep deploy scripts in `scripts/linux/`
- keep frontend apps separated by platform/programme
- include `.env.example`, `.gitignore`, and `README.md`

## Process

1. create root structure
2. separate backend and frontend app folders
3. add docs and scripts folders
4. create env example and readme
5. document deviations if needed
