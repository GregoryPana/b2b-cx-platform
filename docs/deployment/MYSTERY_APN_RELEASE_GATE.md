This is a dependency/evidence checklist, not an acceptance record. The application VM remains internal; approved APN clients may reach HTTPS 443 only. No public route, signed deployment, migration or credential rotation is authorized by this document.

**Release sequence:** review/merge source and pass CI; VM-admin-controlled bootstrap and disposable-VM rehearsal; confirm internal production migration and backup ownership; establish the first newly signed/healthy baseline through separately approved protected workflow; only then allow normal deploy with authenticated fallback. Obtain the explicit deployment approval before *any* workflow dispatch. A failed-release directory is not a fallback. Capture before/after `status`, fresh verification/recovery JSON, service restart and actual source/manifest/database heads; never equate a successful build, local health, or a signed operation with business acceptance.

**APN/device test record:** name the approved device class and APN source scope, TLS trust result and observation time, test shopper ID (not credentials), release ID/full SHA, internal review visit ID, each positive and negative result, incident/503 investigation reference, business owner decision and ops handover. Keep secrets, recovery codes and user personal data out of this record.
